<!-- sdlc:auto:start overview -->
Quick Notes is a small note-taking app generated by the Quorq AI SDLC platform, delivered as two applications in one repository. The frontend is an approved-design Vite + React 19 single-page app that currently runs against seeded sample data rather than a live API. The backend is a FastAPI 0.115 service using SQLAlchemy 2.0 models, Alembic-managed migrations, and a pluggable database (SQLite by default locally, PostgreSQL 16 in tests/deployment); at this stage it only exposes a health check and a seeded-user auth flow (login/me), with all other endpoints scaffolded as typed stubs awaiting implementation.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for npm, Vite 6, React 19 tooling)
- npm
- Python 3.12
- pip (virtualenv recommended)
- Docker and Docker Compose (optional, for the PostgreSQL service in docker-compose.yml)
- PostgreSQL 16 (required to run backend pytest, per TESTING.md; SQLite is fine for ad-hoc local running)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. git clone the repository and cd into it
2. Copy .env.example to .env and fill in any required values
3. cd frontend && npm install
4. cd ../backend && pip install -r requirements.txt
5. Optional: from the repo root, run 'docker compose up -d db' to start a local PostgreSQL 16 instance (user/db 'app', default local password 'app')
6. Start the backend: cd backend && uvicorn app.main:app --reload (uses SQLite at ./app.db unless DATABASE_URL is set)
7. In a separate terminal, start the frontend: cd frontend && npm run dev
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend routes are organized one router per approved architecture component, with one route per endpoint declared in the API spec (see backend/app/routers/).
- Unimplemented routes return a typed StubResponse (endpoint, status, detail) rather than failing, so the service and its OpenAPI doc stay complete during generation.
- All Pydantic request/response models extend ApiModel (app/api_model.py) so JSON fields are camelCase at the API boundary.
- Database schema changes go through Alembic migrations only; the app never uses create_all to modify an existing schema.
- A single DB session per request is provided via the get_db() dependency, opened and closed per call, never at import time.
- DATABASE_URL controls the backend DB: SQLite by default for zero-setup local runs, PostgreSQL in tests/deployment.
- CORS origins are driven by the ALLOWED_ORIGINS env var, defaulting to the local Vite dev server origins.
- Frontend API types/client are generated, not hand-written: npm run gen:api regenerates frontend/src/api/schema.ts and the OpenAPI doc from the backend.
- Session auth token is kept in localStorage (app.ts) and sent as a bearer on calls, taking precedence over the shared project bearer baked into the build.
- Frontend screens live under src/screens/ (one module per approved screen) and are still wired to seeded sample data, not the live API.
- Both apps write JUnit XML test reports to a fixed reports/junit/ folder for the platform's test dashboard; test case IDs (e.g. tc102) appear in test names per TESTING.md.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| `pytest` fails or can't connect to a database in backend/ | Backend tests require PostgreSQL, not the default SQLite file; start one (e.g. `docker compose up -d db`) and set DATABASE_URL accordingly, per TESTING.md. |
| Frontend calls to the API are blocked by the browser with a CORS error | Set the ALLOWED_ORIGINS env var on the backend to include the frontend's origin (defaults to the Vite dev server origins only). |
| Backend fails to start with an error about alembic.ini being missing | Ensure alembic.ini and the alembic/ directory remain alongside app/ (the Dockerfile copies both); they are required to run migrations on startup. |
| `npm run test:e2e` fails because no browser is installed | Run `npm run test:e2e:install` once to fetch the Chromium browser used by Playwright. |
| `npm run build` succeeds but `tsc` would fail | Build does not typecheck; run `npm run typecheck` to catch type errors like untyped `useState({})` before treating the build as production-ready. |
<!-- sdlc:auto:end troubleshooting -->
